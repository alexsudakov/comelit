# Однократная локальная проверка `result` в P2P-ответе

Обычная диагностика не требует сохранения HTTP-ответа: WARNING сообщает только
`SUCCESS`, `TIMEOUT` или `UNKNOWN` и не выводит тело, SDP, токены либо
произвольные значения сервера. Следующую процедуру можно применять только для
разовой локальной проверки уже полученного файла ответа и только на машине,
которой разрешена обработка этих данных.

1. Сохраните ответ в отдельный локальный файл `p2p-response.json` с правами
   `0600`. Не добавляйте файл в репозиторий, тикет, чат или системный журнал.
2. Выведите только классифицированное значение:

   ```sh
   jq -r 'if (.result? | type) != "string" then "UNKNOWN" elif .result == "SUCCESS" then "SUCCESS" elif .result == "TIMEOUT" then "TIMEOUT" else "UNKNOWN" end' p2p-response.json
   ```

   Команда намеренно не показывает неизвестное исходное значение: строка может
   оказаться токеном или иным секретом. Не используйте `cat`, `jq .`, трассировку
   HTTP или копирование тела ответа в логи.
3. После проверки удалите локальный файл штатным безопасным способом для этой
   машины. Не включайте его содержимое в отчёт; достаточно зафиксировать один
   из маркеров `SUCCESS`, `TIMEOUT`, `UNKNOWN`.

Эта процедура не доказывает причину сбоя и не меняет P2P-поток. Маркер
`ROOT_CAUSE=PROVEN` допустим только после отдельного фактического наблюдения и
анализа, а не по одному классифицированному `result`.
