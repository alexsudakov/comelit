# Однократная локальная проверка `result` в P2P-ответе

Эта процедура предназначена только для согласованного локального исследования на
доверенном хосте. Она не является постоянной диагностикой и не разрешает выводить
HTTP-тело, заголовки, OAuth/VIP-токены, UUID или SDP в логи, issue, PR, сообщения и
артефакты CI.

1. Остановить публикацию логов и запись терминала. Убедиться, что на хосте нет
   screen sharing, внешнего сборщика stdout/stderr и автоматической отправки crash
   dump. Не включать `aiohttp` debug/trace logging.
2. Поставить одноразовую точку останова в `async_negotiate_p2p()` сразу после
   успешного `json.loads()` и только для одного ручного P2P-запроса. Не добавлять
   `print`, `_LOGGER.*`, дамп объекта или запись ответа в файл.
3. В локальном отладчике проверить только значение `obj.get("result")` в памяти.
   Не раскрывать и не разворачивать `data`, `sdp`, заголовки, request payload или
   другие поля. Зафиксировать вручную лишь классификацию: `SUCCESS`, `TIMEOUT`,
   `missing` либо `other`; значение класса `other` не копировать.
4. Немедленно удалить точку останова и завершить отладчик. Проверить рабочее
   дерево штатным разрешённым способом и убедиться, что временный код, дампы,
   transcript и файлы с ответом отсутствуют.

Обычная эксплуатационная диагностика должна использовать только ограниченный
WARNING из `_log_response_validation_failure()`. Значение неизвестного `result`
в нём всегда отображается как `UNKNOWN`; успешный ответ не логируется.
