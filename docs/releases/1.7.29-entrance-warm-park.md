# Comelit 1.7.29 — Entrance 60-second warm park

## Purpose

Release 1.7.29 corrects the Mini App tab-switch lifecycle after the 1.7.28
ordinary-camera WebCodecs promotion.

In 1.7.28, an explicitly opened Entrance WebCodecs viewer intentionally stayed
connected when the user moved to «Видеонаблюдение». That allowed the Entrance
WSS/PyAV/VideoDecoder consumer and an ordinary-camera WebCodecs consumer to run
at the same time. A live user observation showed ordinary surveillance opening
quickly and reliably when Entrance had not been opened, while opening Entrance
first could lead the ordinary viewer into fallback and ultimately an HLS HTTP
error.

1.7.29 removes that browser-side overlap without forcing every return to
Entrance through the full cold Comelit bootstrap.

## Tab-switch lifecycle

When the Entrance camera is open and the user switches to
«Видеонаблюдение»:

```text
active Entrance WebCodecs viewer
  -> acquire miniapp_webcodecs_park lease
  -> disconnect Entrance DOM viewer
  -> close Entrance WSS
  -> stop Entrance PyAV reader
  -> close Entrance VideoDecoder
  -> start ordinary surveillance viewer
```

The browser therefore has no hidden Entrance decoder/WSS continuing behind the
surveillance tab.

The park lease is bounded to:

```text
60 seconds
```

## Fast return to Entrance

If the user returns to «Домофон» before the park timeout:

```text
existing Comelit media transport remains active
  -> acquire new miniapp_webcodecs viewer lease
  -> release miniapp_webcodecs_park lease
  -> attach fresh Entrance WebCodecs WSS/PyAV/VideoDecoder
```

The new viewer lease is acquired before the park lease is dropped. The
`ComelitMediaSessionManager` therefore never reaches zero leases during the
handoff and does not intentionally repeat the cold P2P/PseudoTCP/CTPP bootstrap.

If the user does not return within 60 seconds, the park lease expires. With no
other media lease, the existing manager performs its normal full teardown and
restores the persistent Ring/Door listener.

The manager's existing 600-second absolute media deadline remains
authoritative. A session already near that deadline can therefore end before
the full 60-second park window.

## Scope boundary: warm transport, not protocol-level RTP pause

This release does **not** invent a proprietary RTPC stop/reopen operation.

During the 60-second park:

- the Telegram WebView receives no Entrance video;
- the Entrance browser WebSocket is closed;
- the Entrance PyAV reader is closed;
- the Entrance browser VideoDecoder is closed;
- the existing Comelit on-demand media transport inside Home Assistant remains
  active under the park lease.

Therefore this release removes the second browser-side video pipeline and
decoder. It does not yet claim that upstream Comelit RTP is stopped while the
P2P/PseudoTCP/CTPP session remains established.

A future optimization of the form:

```text
stop Entrance RTP
-> keep established CTPP
-> later reopen RTP on the same CTPP
```

requires separate protocol evidence and live validation before production use.

## Failure behavior

The warm park is an optimization, not a new safety dependency.

If the park request cannot be established, the card still disconnects the
Entrance viewer before starting ordinary surveillance. The existing Entrance
viewer lease then follows normal teardown. Returning to Entrance is cold in
that case rather than leaving two browser media consumers active.

Explicit «Скрыть камеру», terminal Entrance WebCodecs failure, Mini App close,
and Entrance HLS fallback do not request a warm park and retain their normal
cleanup/fallback behavior.

## Listener and Door/Gate boundary

A separately bootstrapped Entrance media session still owns the exclusive
Comelit connection while the park lease is held. The persistent Ring/Door
listener therefore remains intentionally paused during the bounded warm window
and is restored by the existing manager after final teardown.

No Door or Gate protocol behavior is added or changed by this release. The
existing one-shot and no-automatic-retry rules remain in force.

## Validation

Feature PR #275 adds and passes repository coverage for:

- one 60-second `miniapp_webcodecs_park` lease;
- Entrance viewer lease + park lease overlap before browser disconnect;
- releasing the viewer while the park lease remains keeps the same manager
  transport active;
- returning to Entrance acquires the new viewer lease before releasing park;
- warm return does not increment the fake transport start count;
- park expiry releases the last lease and returns the fake manager to inactive;
- tab switch calls the authenticated park endpoint before Entrance disconnect;
- old Entrance WebSocket is closed before ordinary surveillance playback;
- ordinary WebCodecs remains the only browser-side primary after the switch;
- updated offline-safety frontend lifecycle contract;
- Mini App browser regressions;
- Validate HACS.

No native binary, native signaling profile, Door/Gate operation, Home Assistant
restart, deploy, or live camera run is performed by repository release
preparation.

## Deployment boundary

Publishing this release does not itself install it into Home Assistant.

After updating to 1.7.29 through HACS and loading the new integration/frontend
runtime, production acceptance should verify:

1. cold Entrance still opens normally;
2. switch Entrance -> «Видеонаблюдение» and open an ordinary camera;
3. no ordinary-camera fallback/HTTP error occurs;
4. return to «Домофон» within 60 seconds is materially faster than a cold
   Entrance open;
5. after remaining away for more than 60 seconds, the next Entrance open is
   allowed to be cold because the parked lease has expired.
