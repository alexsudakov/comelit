# 1.6.2 — Mini App session / Home Assistant IP-ban fix

Status: **release-ready / production canary required**  
Release line: **1.6.2**

## Observed production symptom

After updating/restarting Home Assistant while a Telegram Mini App WebView remained open, Home Assistant logged repeated warnings from `homeassistant.components.http.ban` for:

`/api/comelit/miniapp/state`

The requests repeated on the Mini App state polling interval.

## Root cause

Mini App sessions are intentionally in-memory and are invalidated by Home Assistant restart. They also expire after 15 minutes.

An already-open WebView continued polling with the old Mini App session cookie. The embedded integration rejected the integration-owned session by raising `web.HTTPUnauthorized`.

Home Assistant's global HTTP ban middleware treats a raised `HTTPUnauthorized` as a failed Home Assistant authentication attempt. Therefore a stale Mini App session incorrectly entered HA's login-failure/IP-ban accounting path.

## Fix

1. Integration-owned Mini App session failures now fail closed with HTTP 403 rather than the raised-401 Home Assistant login path.
2. Failed Telegram Mini App signature/allowlist authentication uses the same non-HA-auth rejection path.
3. When the WebView receives 403 from periodic state refresh, it stops the polling timer.
4. The user is told to close and reopen the Mini App, obtaining fresh Telegram initData and a new in-memory session.
5. No automatic reauthentication or retry loop is introduced.

## Unchanged contracts

- Telegram Ed25519 signature validation is unchanged.
- Telegram user allowlist is unchanged.
- Session lifetime remains 15 minutes.
- Door/Gate one-shot nonce and no-retry rules are unchanged.
- Camera transport and HLS capability proxy are unchanged.
- Bundled hls.js playback from 1.6.1 is unchanged.

## Verification

The fix passed:

- Mini App tests;
- explicit regression assertion that Mini App session handling does not raise `web.HTTPUnauthorized`;
- JavaScript syntax checks;
- HACS validation;
- offline-safety.

## Production canary

After updating to 1.6.2 and restarting Home Assistant:

1. close any Mini App window that survived the restart;
2. open «Домофон» again from Telegram;
3. verify normal UI/state refresh;
4. leave the Mini App open until the 15-minute session expires;
5. verify that polling stops and the UI asks to reopen the Mini App;
6. verify that no new `homeassistant.components.http.ban` warnings are generated by `/api/comelit/miniapp/state`.

Camera and Door/Gate are not required for this auth-boundary canary.
