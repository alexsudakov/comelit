# Comelit 1.7.12 — P122 active-media Door eligibility corrective

## Summary

1.7.12 is a patch release for the on-demand Entrance Door path introduced in
1.7.11.

Live validation of 1.7.11 proved that the on-demand camera session was fully
active, but the Door command was rejected before transmission:
`P122_ONDEMAND_DOOR_COMMAND_ACCEPTED=false`,
`P122_ONDEMAND_DOOR_RESULT=REJECTED_NOT_READY`, and `WRITE_COUNT=0`.

The root cause was an internal signaling-state mismatch. P85 intentionally
marks successful production media as `ENTRANCE_SIGNAL_DONE` while keeping RTP
forwarding active, but the new P122 Door gate still required the older
`ENTRANCE_SIGNAL_OBSERVE_MEDIA` state.

1.7.12 aligns P122 with the actual production active-media lifecycle.

## Corrective

The P122 eligibility evaluator now requires the production active-media state
`ENTRANCE_SIGNAL_DONE` and retains the existing fail-closed conditions for
media forwarding, RTPC completion, PseudoTCP state, CTPP availability,
conflicting TX, refresh state, initial signaling, and one-shot Door state.

The corrective does not restore the old signaling state and does not weaken
P85.

## Reject diagnostics

Rejected P122 Door operations now emit a bounded safe diagnostic marker:

`P122_ONDEMAND_DOOR_REJECT_GATE=<SAFE_ENUM>`

The enum distinguishes the eligibility condition that blocked the operation
without exposing protocol payloads, logical addresses, SDP, credentials, or
other sensitive values.

Home Assistant allowlists this marker into the existing Door diagnostics.

## Safety

Unchanged safety properties:

- Entrance only for the on-demand media Door profile.
- Gate remains fail-closed during separately bootstrapped on-demand media.
- Exactly one Door transport attempt per explicit user operation.
- No automatic retry.
- Existing media CTPP is reused.
- No second P2P session.
- No second CTPP open.
- Protocol acknowledgement is not treated as proof of physical opening.
- Physical effect remains user-observed acceptance evidence.

The attached physical-call `CALL_TIME_SINGLE` / R66 path is not changed by
this release.

## Post-update acceptance

After HACS updates the integration to 1.7.12 and Home Assistant restarts, run
one bounded physical acceptance test:

1. ensure there is no active physical Ring;
2. explicitly open `camera.comelit_entrance`;
3. wait until on-demand media is active;
4. press Entrance Door exactly once;
5. record whether the physical entrance door opened.

The expected transport-side evidence is one accepted P122 operation, one
network write, no retry, and no fail-closed eligibility rejection.
