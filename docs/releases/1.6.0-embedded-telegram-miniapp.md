# 1.6.0 — Embedded Telegram Mini App

Status: **release-ready / opt-in capability**  
Release line: **1.6.0**  
Scope: Telegram Mini App embedded directly in the Home Assistant Comelit integration

## Summary

1.6.0 moves the Telegram Mini App into `custom_components/comelit` and removes the previously proposed standalone application-server architecture.

Production remains:

~~~text
Telegram Mini App
        |
        | HTTPS
        v
Home Assistant HTTP server
        |
        v
custom_components/comelit
        |
        +-- Mini App auth/session/views
        +-- shared comelit-card.js
        +-- Home Assistant state / registry / services / camera stream
        |
        v
Comelit runtime
~~~

The Mini App is **disabled by default**. Updating from 1.5.20 therefore does not expose a public Mini App route until the user explicitly enables and configures it in the Comelit Options Flow.

## Architecture changes

The release deliberately has no permanent third Comelit application layer.

Removed from the production design:

- standalone FastAPI/Uvicorn gateway;
- Docker runtime for Mini App;
- Home Assistant Long-Lived Access Token;
- Home Assistant REST/WebSocket client inside a gateway;
- Telegram bot token requirement for Mini App authentication.

Both Lovelace and Telegram continue to use the exact same bundled UI artifact:

~~~text
custom_components/comelit/frontend/comelit-card.js
~~~

The Telegram host supplies only the narrow `hass` compatibility surface already required by that card.

## Telegram authentication

Raw `Telegram.WebApp.initData` is validated inside Home Assistant with Telegram's documented third-party Ed25519 validation algorithm.

The integration requires:

- the configured numeric Telegram bot ID;
- Telegram's pinned production Ed25519 public key;
- a bounded `auth_date` window;
- a server-side allowlist of Telegram numeric user IDs.

`initDataUnsafe` is not trusted.

No Telegram bot token is stored by the Mini App implementation.

After successful validation, Home Assistant creates a random opaque in-memory session:

- 15-minute lifetime;
- `HttpOnly`;
- `Secure`;
- `SameSite=Strict`;
- scoped to `/api/comelit/miniapp`.

Home Assistant restart intentionally invalidates all Mini App sessions.

## Door/Gate safety

The browser cannot request an arbitrary Home Assistant entity.

The public Mini App action surface is the closed semantic set:

~~~text
POST /api/comelit/miniapp/door/entrance
POST /api/comelit/miniapp/door/gate
~~~

The integration resolves the current button entity from the accepted stable Comelit unique IDs and requires the entity to report `standard_press_allowed=true`.

One accepted HTTP request invokes exactly one existing `button.press`. There is no automatic retry.

Each session also owns a one-time Door action nonce. The nonce is consumed and rotated before the Home Assistant service call. Replaying an already-consumed request therefore cannot produce a second Door invocation, including after a network ambiguity.

A successful software call does not assert a physical Door effect.

## Camera and HLS

The Mini App uses Home Assistant's normal camera stream path:

~~~text
async_request_stream(hass, entity_id, HLS_PROVIDER)
~~~

For `camera.comelit_entrance`, this preserves the already accepted camera-owned media lifecycle:

~~~text
explicit viewer
-> attached Ring reuse when available
   otherwise bounded on-demand media
-> HA Stream / HLS
-> viewer idle/remove
-> existing camera-view cleanup
~~~

The raw Home Assistant HLS capability path is never serialized to Telegram.

Instead, Home Assistant creates a random media grant bound to the authenticated Mini App session and exposes only `/api/comelit/miniapp/media/<media-id>/...`.

The proxy accepts only the closed HLS resource set required by HA Stream playlists, initialization fragments and numeric media parts/segments.

## Surveillance cameras

The Comelit Options Flow can identify a Home Assistant label by ID or name. Only `camera.*` registry entries carrying that label are included in the Mini App surveillance surface. The integration does not expose all Home Assistant cameras.

## Configuration

The 1.6.0 Options Flow adds:

~~~text
Enable Telegram Mini App
Telegram bot ID
Allowed Telegram user IDs
Home Assistant camera label
~~~

No new long-lived secret is required.

## Safety and compatibility invariants retained

1. Door/Gate operations remain one-shot and have no automatic retry.
2. Protocol acknowledgement is not physical Door proof.
3. Intercom media remains on-demand only.
4. Home Assistant thumbnails/preload must not start the entrance camera.
5. Separately bootstrapped media retains the 600-second absolute ceiling.
6. Attached Ring media continues to reuse the existing inbound transaction.
7. Persistent Ring/Door listener ownership rules are unchanged.
8. Existing Lovelace behavior and `comelit-card.js` remain the primary UI contract.

## Verification

The release line passed:

- dedicated Ed25519 authentication tests;
- session expiry and one-time action nonce tests;
- session-bound media-grant tests;
- embedded controller runtime-contract tests against a fake Home Assistant boundary;
- state/registry data-leak filtering tests;
- semantic Door -> exactly one `button.press` tests;
- fail-closed unavailable/unknown Door tests;
- Home Assistant HLS request/proxy capability tests;
- Mini App JavaScript parse;
- bundled shared-card JavaScript parse;
- `offline-safety`;
- HACS validation.

No production Door/Gate actuation is part of these release tests.

## Deployment acceptance still required

The embedded Mini App code is release-ready, but the following installation-specific items remain live acceptance tasks rather than pre-release assumptions:

1. the chosen external Home Assistant HTTPS URL must serve `/api/comelit/miniapp` to Telegram;
2. Telegram must accept the configured Mini App URL;
3. login/session establishment must work in the target Telegram clients;
4. the shared Comelit card must render correctly in the Telegram WebView;
5. native HLS playback must be tested on the target Android/iOS Telegram WebViews;
6. if a target WebView lacks native HLS, a bundled HLS player may be added without changing the backend security architecture.

Door/Gate is deliberately excluded from the first Mini App canary.

## Recommended rollout

First canary:

~~~text
update to 1.6.0
-> restart Home Assistant
-> confirm normal Comelit listener READY
-> configure bot ID + one allowed Telegram user
-> enable Mini App
-> open Mini App
-> verify authentication + idle state UI
-> close Mini App
~~~

Do **not** open a camera and do **not** press Entrance/Gate in this first canary.

Second canary, after the first passes:

~~~text
open entrance viewer explicitly
-> confirm video or record WebView playback limitation
-> close viewer
-> confirm media teardown
-> confirm listener READY
~~~

Door/Gate acceptance remains a separate explicitly authorized phase.

## Rollback

The lowest-risk rollback for a Mini App problem is simply:

~~~text
Comelit Options
-> disable Telegram Mini App
~~~

Because the capability is opt-in, this removes the public Mini App surface without altering the existing Ring/Door/camera integration.

If an integration-level regression is discovered, roll back the installed package to 1.5.20.
