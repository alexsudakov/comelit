# Comelit 1.7.18 — server-side MSE startup milestones

## Purpose

1.7.18 is a diagnostic-only patch.

It does not change:

- MSE startup timeouts;
- camera source preparation;
- WebRTC behavior;
- HLS behavior;
- fallback order;
- Door/Gate paths;
- the Comelit entrance-camera lifecycle.

## Why

Live testing on 1.7.17 still showed:

```text
mse_connect
-> 8001 ms
-> mse_fallback reason=mse_negotiation_failed
```

with no `mse_ready`.

That remained unchanged after:

- correcting Home Assistant go2rtc runtime/session binding;
- aligning codec identifiers with upstream go2rtc;
- switching to stage-relative startup deadlines;
- mirroring HA core's Generic Camera `ffmpeg:` source wrapper.

The remaining uncertainty is therefore inside the server-side MSE startup path.

## New diagnostic marker

1.7.18 adds:

```text
COMELIT_MINIAPP_DIAG_SERVER
```

with a closed event set:

```text
mse_command_received
mse_source_resolved
mse_stream_registered
mse_upstream_ws_open
mse_negotiation_forwarded
mse_upstream_reply
mse_upstream_chunk
```

Each event contains only:

- entity_id;
- bounded elapsed_ms;
- bounded stage_ms.

No stream source, camera URL, camera IP, credentials, go2rtc management URL,
SDP, ICE candidate, cookie, Telegram initData, or token is serialized.

## Interpretation

Expected successful server path:

```text
mse_command_received
-> mse_source_resolved
-> mse_stream_registered
-> mse_upstream_ws_open
-> mse_negotiation_forwarded
-> mse_upstream_reply
-> mse_upstream_chunk
```

The first missing milestone identifies the failing phase.

Examples:

- no `mse_source_resolved`:
  source resolution is blocked or failing;
- source resolved but no `mse_stream_registered`:
  go2rtc stream registration is blocked or failing;
- stream registered but no `mse_upstream_ws_open`:
  go2rtc WS open is blocked or failing;
- WS open + negotiation forwarded but no upstream reply:
  go2rtc producer/codec negotiation is the next target;
- upstream reply but no chunk:
  producer started but media is not flowing.
