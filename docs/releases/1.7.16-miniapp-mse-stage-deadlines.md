# Comelit 1.7.16 — stage Mini App MSE startup deadlines around cold go2rtc

## Production evidence

A bounded live capture on 1.7.15 for `camera.parking_6048` captured the complete
viewer lifecycle.

Observed MSE sequence:

```text
mse_connect   = 0 ms
mse_ready     = not observed
mse_first_chunk = not observed
mse_first_frame = not observed
mse_fallback  = 3001 ms
reason        = mse_negotiation_failed
```

The same attempt then entered the WebRTC fallback. Home Assistant WebRTC needed
about 5.5 seconds from offer to answer, received zero RTP bytes, and fell back
again. HLS eventually produced the first frame at about 41.8 seconds.

That evidence proved that the old 3 second MSE negotiation deadline was shorter
than the real cold HA/go2rtc startup path on this installation.

## Stage-relative startup deadlines

1.7.15 started all MSE timers from viewer startup:

```text
negotiation: 3 s
first chunk: 6 s absolute
first frame: 12 s absolute
```

That made later budgets partially expire before their stages were reachable.

1.7.16 changes the model to:

```text
viewer start -> MSE negotiation: 8 s
mse_ready -> first binary chunk: 8 s
first binary chunk -> first decoded/rendered frame: 8 s
```

Only the active stage consumes its timeout budget.

## go2rtc hot path

The HA-managed go2rtc adapter no longer performs a separate `GET /api`
health/version request before both:

- `PUT /api/streams`;
- opening `/api/ws?src=...`.

The concrete operation itself is now the bounded compatibility check.

The authoritative Home Assistant `Go2RtcConfig(url, session)` runtime session
and UnixConnector introduced in 1.7.15 remain unchanged.

## Regression coverage

Feature PR #249 verifies:

- negotiation can remain in progress for 7 seconds without fallback;
- negotiation still fails boundedly at approximately 8 seconds if no response
  arrives;
- the first-chunk budget starts at `mse_ready`, not viewer startup;
- the first-frame budget starts at `mse_first_chunk`;
- the existing MSE success path remains MSE-only with no RTCPeerConnection;
- WebRTC/HLS fallback scenarios remain intact;
- HA-managed go2rtc uses its authoritative runtime session;
- the hot path performs no separate `GET /api` probe.

Required CI:

- `miniapp`: PASS;
- `offline-safety`: PASS;
- `Validate HACS`: PASS.

One first browser run was cancelled while Playwright dependencies were being
installed. The next run reached the regression suite and hit a pre-existing
scheduler-sensitive HLS autoplay assertion; an unchanged rerun passed the full
browser suite, including the new MSE tests. No production code was changed to
mask that transient test result.
