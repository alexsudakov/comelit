# 1.7.0 — Mini App on-demand surveillance WebRTC

Status: **release-ready / production canary required**  
Release line: **1.7.0**

## Production observations behind this release

The embedded Telegram Mini App was live-validated through:

- Telegram authentication and embedded UI;
- Comelit entrance-camera HLS playback;
- HLS.js fallback in Telegram WebViews;
- stale-session/IP-ban corrective;
- ordinary surveillance camera discovery through a Home Assistant label.

Two usability issues remained for ordinary surveillance cameras:

1. tall/rotated parking-camera video could exceed the mobile viewport;
2. ordinary cameras had a slow cold start through Home Assistant HLS.

Permanent Home Assistant stream preload was deliberately rejected as the default
solution because it would keep ordinary camera streams and HA stream workers
active continuously.

## Viewport fix

The Mini App video element now has a bounded mobile viewport height and
`object-fit: contain`.

A tall/rotated stream is scaled down to fit rather than forcing the user to
scroll through a video taller than the visible Telegram viewport. Full-screen
video controls remain available.

## On-demand WebRTC path

Ordinary surveillance cameras now prefer Home Assistant's standard WebRTC
provider.

On HAOS installations using `default_config`, Home Assistant includes its
managed go2rtc component. The Mini App does not connect to go2rtc management
interfaces directly. Instead it exposes a session-bound signaling WebSocket:

`/api/comelit/miniapp/camera/{entity_id}/webrtc`

The server validates the existing Telegram Mini App session and camera
allowlist, then delegates signaling to the selected Home Assistant Camera
entity.

Conceptual path:

```text
Telegram Mini App
  -> authenticated Comelit Mini App WebSocket
  -> Home Assistant Camera WebRTC provider
  -> HA-managed go2rtc
  -> ordinary camera RTSP source
```

The viewer creates a receive-only WebRTC video peer connection. When the viewer
is removed, the signaling socket is closed and the Home Assistant WebRTC
session is explicitly closed.

This is on-demand use. This release does not enable Home Assistant camera
preload.

## Fallback

If:

- the Telegram WebView lacks WebRTC;
- the camera has no Home Assistant WebRTC provider;
- signaling/ICE fails; or
- the WebRTC signaling socket cannot be established,

the ordinary surveillance viewer falls back to the existing session-bound Home
Assistant HLS path.

The camera label shows `WebRTC` or `HLS` once playback starts so the
production canary can identify the transport actually in use.

## Security / lifetime

- WebRTC signaling requires the existing Mini App session cookie.
- Only cameras already admitted by the Mini App camera allowlist/label may be
  requested.
- The Comelit entrance camera is explicitly excluded from this WebRTC path.
- A WebRTC signaling session is bounded by the Mini App session expiry and is
  closed when that session expires.
- No Home Assistant Long-Lived Access Token is introduced.
- No go2rtc username/password or management API is exposed to the browser.
- HLS capability paths remain session-bound behind the existing proxy.

## Unchanged Comelit safety contracts

The following are unchanged:

- Comelit entrance media remains on-demand and owned by
  `ComelitMediaSessionManager`;
- listener/media exclusive ownership remains unchanged;
- the 600-second entrance-media ceiling remains unchanged;
- Door/Gate one-shot and no-auto-retry behavior remains unchanged;
- this release does **not** enable Door actuation during a separately
  bootstrapped entrance-media session.

## Production canary

After updating to 1.7.0 and restarting Home Assistant:

1. open Telegram Mini App -> «Видеонаблюдение»;
2. select one ordinary camera;
3. verify the video fits within the viewport;
4. note whether the camera label shows `WebRTC` or `HLS`;
5. compare time-to-first-frame with 1.6.2;
6. switch to a second ordinary camera and verify the first viewer is released;
7. leave «Видеонаблюдение» and verify no ordinary camera stream is intentionally
   kept open by the Mini App;
8. separately verify the entrance camera still uses its existing HLS path.

Door/Gate actuation is outside this canary.
