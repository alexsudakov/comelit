# 1.6.1 — Telegram Mini App HLS playback

Status: **release-ready / production canary required**  
Release line: **1.6.1**  
Scope: Telegram WebView playback only

## Observed production symptom

The embedded Mini App authentication/UI canary passed on 1.6.0.

During the first entrance-camera canary:

- the first request hit the existing one-time preload fail-closed path;
- the second explicit request successfully started the Comelit media session;
- the UI showed `Listener: paused_media`;
- the HTML5 video element remained at `0:00`.

That combination localizes the 1.6.0 defect after Home Assistant stream creation and before successful WebView playback.

## Root cause

The 1.6.0 Mini App host assigned the proxied Home Assistant `.m3u8` URL directly to a plain HTML5 `video` element.

Native HLS support is not reliable across Telegram WebViews, especially Chromium-based desktop/Android environments.

## Fix

1. Bundle pinned `hls.js 1.7.3` inside the Comelit frontend.
2. Serve it from the existing same-origin path:
   `/api/comelit/frontend/miniapp/vendor/hls.min.js`.
3. Use hls.js / MediaSource when supported.
4. Keep native HLS as the fallback for platforms that provide it directly.
5. Run hls.js with `enableWorker: false`, so the existing restrictive CSP does not need a new blob-worker permission.
6. Destroy the hls.js instance when the camera viewer is removed.
7. Surface fatal HLS errors in the Mini App instead of leaving a silent `0:00` player.
8. Do not automatically reopen the Comelit camera after a fatal playback error.

## Supply-chain boundary

The vendored bundle was extracted from the official hls.js v1.7.3 GitHub release archive.

The archive was verified against the SHA-256 published by GitHub:

`abbda85f3e9b8325fc6b8dbf4fa612ea87144ebad93c2150594e64aad58ec529`

The Apache-2.0 license is stored alongside the vendored asset.

There is no runtime CDN dependency.

## Unchanged safety contracts

1. Telegram Ed25519 authentication and allowlist are unchanged.
2. Mini App sessions and one-time Door nonce are unchanged.
3. Door/Gate remains exactly one existing `button.press` per explicit accepted click.
4. Door/Gate has no automatic retry.
5. The browser still never receives the raw Home Assistant `/api/hls/<token>` capability.
6. Camera startup still goes through Home Assistant `async_request_stream(..., HLS_PROVIDER)`.
7. Comelit media ownership, attached Ring reuse and the 600-second ceiling are unchanged.
8. No automatic camera reopen is introduced by the playback fallback.

## Production canary

After updating to 1.6.1 and restarting Home Assistant:

1. verify normal Comelit listener READY;
2. open the Telegram Mini App;
3. explicitly open the entrance camera once;
4. if the first request is the one-time preload fail-closed request, close/reopen explicitly once;
5. confirm moving video rather than a `0:00` player;
6. close the camera;
7. confirm media teardown and listener return to READY.

Do not press Entrance or Gate during this camera canary.

If playback still fails, the 1.6.1 UI will expose the hls.js fatal error detail, allowing the next diagnosis to distinguish playlist/proxy/codec/MSE failures.
