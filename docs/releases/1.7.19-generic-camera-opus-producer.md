# Comelit 1.7.19 — mirror Home Assistant Generic Camera Opus producer

## Production evidence

1.7.18 localized the remaining MSE failure inside HA-managed go2rtc.

For `camera.parking_6048`, the server-side path completed in about 60 ms:

```text
mse_command_received
mse_source_resolved
mse_stream_registered
mse_upstream_ws_open
mse_negotiation_forwarded
```

No `mse_upstream_reply` or `mse_upstream_chunk` followed before the existing
8 s MSE negotiation deadline.

A separate capture including Home Assistant go2rtc logging produced no go2rtc or
ffmpeg warning/error during the same attempt.

## Remaining parity difference

Home Assistant core does not register a Generic Camera with only one source.

It registers:

```text
ffmpeg:<camera.stream_source()>
ffmpeg:<camera-identifier>#audio=opus#query=log_level=debug
```

Comelit 1.7.18 mirrored only the first producer.

The known `camera.parking_6048` stream contains H.264 video and PCMA/G.711
A-law audio. The browser MSE codec request offers H.264 plus AAC/FLAC/Opus audio
families, not PCMA.

## Fix

For Generic Camera entities, 1.7.19 now registers the same producer pattern with
Comelit's opaque stream identifier:

```text
ffmpeg:<stream_source>
ffmpeg:<internal_stream>#audio=opus#query=log_level=debug
```

The go2rtc adapter sends both sources in one `PUT /api/streams` request using
repeated `src` query parameters, which is the multi-source form supported by
go2rtc.

Other ordinary camera integrations keep exactly one unchanged resolved source.

## Unchanged behavior

1.7.19 does not change:

- the 8 s MSE stage deadlines;
- browser codec probing;
- Mini App MSE protocol;
- WebRTC fallback;
- HLS fallback;
- 1.7.18 server-side milestone diagnostics;
- the Comelit entrance-camera lifecycle;
- Door/Gate paths.

Camera URLs and credentials remain server-side and are not added to diagnostics
or browser payloads.
