# 1.5.20 — Entrance camera startup stabilization

Status: **stable / live-validated**  
Release line: **1.5.20**  
Scope: entrance intercom cold-start latency and bounded diagnostics

## Summary

This release freezes the camera-startup optimizations that were validated through bounded one-shot production canaries. It does not change the Home Assistant entity model, Door/Gate semantics, media ownership model, 600-second absolute media ceiling, or the rule that intercom media is on-demand only.

On the reference installation, the explicit entrance-camera cold path from Home Assistant request to the first decodable frame improved from **11.219 s** to **6.858 s**, a reduction of **4.361 s (38.9%)**. These numbers describe the validated reference installation and are not a latency guarantee for other networks or Comelit installations.

## Accepted stable startup baseline

The following behavior is accepted for the 1.5.20 stable line:

- entrance signaling settle is **1000 ms**;
- remote SDP is consumed on first complete atomic-file visibility instead of waiting for two additional stable-size polling ticks;
- the libnice STUN initial timeout is temporarily set to **250 ms only during candidate gathering** and is restored to **500 ms before connectivity checks continue**;
- gathering keeps the same candidate classes: the live canary observed host candidates and one server-reflexive candidate;
- PseudoTCP still starts only at libnice **READY**, not at **CONNECTED**;
- automatic protocol retry remains disabled;
- Door and Gate actions remain isolated from media startup.

The gather-timeout live canary measured:

- first host -> first server-reflexive candidate: **46 ms**;
- server-reflexive candidate -> gathering done: **1003 ms**;
- gather call -> gathering done: **1049 ms**;
- ICE CONNECTED -> READY: **1990 ms**;
- request -> first decodable frame: **6858 ms**;
- clean media teardown and listener READY restoration.

The temporary gathering timeout was observed as set to 250 ms and restored to 500 ms during the same real session.

## Diagnostic baseline retained

The stable line keeps bounded camera-startup instrumentation so future changes can be compared against known boundaries without changing protocol behavior. The retained diagnostics cover helper startup, candidate gathering, cloud negotiation, remote SDP handling, libnice CONNECTED/READY, PseudoTCP, CTPP registration, entrance signaling, RTPC control, RTP arrival, and first decodable frame.

Diagnostics must not log SDP contents, candidate addresses, credentials, tokens, or raw authorization material.

## Deliberately deferred optimizations

The following are **not** part of 1.5.20 and must not be inferred from the successful canaries:

- starting PseudoTCP at libnice CONNECTED or merely on selected-pair availability;
- reducing gathering timeout below 250 ms;
- reducing the 1000 ms entrance signaling settle further;
- trickle ICE or sending an offer before full gathering;
- changing STUN/TURN servers or candidate filtering.

The largest measured remaining window is libnice **CONNECTED -> READY (~1.99 s)**. Static analysis showed that a selected pair exists at CONNECTED, but the pair can still change before READY. The current PseudoTCP path has no proven safe rebinding mechanism, so early start remains deferred.

## Safety and lifecycle invariants

The stable release retains the existing production invariants:

- one upstream intercom media session at a time;
- persistent listener paused only for separately bootstrapped on-demand media ownership and restored after confirmed teardown;
- no automatic media/protocol retry;
- no Door action emitted from the media path;
- Gate remains a separately validated target;
- Home Assistant thumbnails and preload do not start intercom media;
- the absolute media-session ceiling remains 600 seconds.

## Release acceptance

The code line promoted to this release passed focused tests, the full repository regression suite, offline safety checks, HACS validation, reproducible native-helper builds, and bounded production live validation. The production canary completed the full media path, clean teardown, and listener restoration without rollback.
