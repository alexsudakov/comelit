# Comelit 1.7.26 — direct Entrance WebCodecs canary

## Purpose

Release 1.7.26 extends the experimental Telegram Mini App WebCodecs transport
from ordinary Home Assistant cameras to the exact Comelit Entrance camera.

The ordinary-camera path was live-validated in 1.7.25 on
`camera.parking_6048`: 1404/1404 H.264 access units decoded, zero sequence
gaps, zero drops, smooth 1080p playback and no irreversible positive WSS
transport drift. The next question is therefore the proprietary Comelit
bootstrap and the handoff from its native H.264 RTP into the already-proven
WSS/WebCodecs path.

## Experimental Entrance path

The new bounded path is:

```text
explicit Mini App Start
  -> existing Mini App auth/session boundary
  -> one WebCodecs session-registry lease
  -> ComelitMediaSessionManager.async_acquire(
       panel="entrance",
       reason="miniapp_webcodecs"
     )
  -> existing listener pause / exclusive on-demand bootstrap
  -> existing ComelitEntranceMediaTransport
  -> existing native helper PT99 H.264 RTP
  -> existing H264RecoveryRtpShim
  -> /run/comelit-media/local-rtp.sdp
  -> PyAV SDP/RTP demux only
  -> H.264 Annex-B access units
  -> binary WSS protocol v2
  -> Telegram Android WebView VideoDecoder
  -> canvas
```

The normal `camera.comelit_entrance.async_create_stream()` / HA Stream / HLS
path is not used by this experimental WebCodecs route.

The native helper and recovery shim are unchanged.

## Zero-transcode boundary

PyAV is used only to open the existing local SDP/RTP source, identify the H.264
stream, demux compressed H.264 packets, normalize AVCC/Annex-B representation
and preserve SPS/PPS handling.

There is no video decode, encode, re-encode, scale or filter operation on Home
Assistant.

The SDP input uses a closed protocol whitelist:

```text
file,udp,rtp
```

The local SDP path and contents remain server-side and are never serialized to
the browser.

## Media ownership

The Entrance WebCodecs path does not create a second media-session owner.

It acquires exactly one lease from the existing
`ComelitMediaSessionManager` with reason:

```text
miniapp_webcodecs
```

The manager remains authoritative for:

- pausing the persistent listener before a separately bootstrapped on-demand
  session;
- one active on-demand Comelit session;
- the existing native transport;
- the 600-second absolute hard ceiling;
- teardown;
- listener restoration after confirmed teardown.

The Mini App canary itself remains 60 seconds.

The path requires the manager to be inactive before the acquire. An active
on-demand session or attached/transition ownership is rejected fail-closed.
There is no automatic media retry.

## Client-close cleanup

After the initial `{"type":"webcodecs","value":"h264"}` command, the Entrance
endpoint runs a bounded WebSocket close watcher.

A client close, navigation or Stop wakes the server media loop immediately.
Cleanup order is:

```text
client close / Stop / timeout / error
  -> cancel and close local PyAV source
  -> release miniapp_webcodecs manager lease
  -> existing manager transport teardown
  -> existing listener restore contract
```

No post-start client command is accepted by the watcher. Any unexpected
post-start message ends this experimental media ownership fail-closed.

## Mini App UI

The WebCodecs camera selector now includes the exact Comelit Entrance camera in
addition to the ordinary surveillance allowlist.

Other Comelit intercom/gate camera identities remain rejected.

Opening the tab or merely selecting Entrance does not start Comelit media.
Only the explicit `Запустить тест` action opens the WebSocket and, after the
validated start command, allows the server to acquire the manager lease.

## Diagnostics

For ordinary cameras the existing fields remain unchanged.

For Entrance, the server sends an additional bounded control milestone:

```text
intercom_media_ready
```

It is emitted only after the manager acquire has returned successfully and the
existing media transport is active with a ready local SDP.

The final canary block includes:

```text
SOURCE_KIND=comelit_entrance_rtp

WS_CONNECT_MS=...
INTERCOM_MEDIA_READY_MS=...
INTERCOM_MEDIA_READY_SERVER_MS=...
INTERCOM_MEDIA_TO_SOURCE_OPEN_MS=...

SOURCE_OPEN_MS=...
FIRST_SOURCE_PACKET_MS=...
FIRST_BINARY_MS=...
FIRST_DECODED_FRAME_MS=...

SOURCE_PTS_DRIFT_*=...
SERVER_QUEUE_DRIFT_*=...
TRANSPORT_DRIFT_*=...

COMELIT_ENTRANCE_OPEN=true
COMELIT_MEDIA_STARTED=true
DOOR_ACTIONS=0
GATE_ACTIONS=0
```

`INTERCOM_MEDIA_READY` separates the proprietary Comelit bootstrap from the
local SDP / WSS / browser decode portion of startup.

These metrics do not claim physical glass-to-glass latency.

## Existing production paths remain unchanged

Release 1.7.26 does not replace:

- the normal Comelit Entrance HLS viewer;
- ordinary-camera MSE -> WebRTC -> HLS fallback;
- attached inbound Ring media ownership;
- the native helper protocol implementation;
- the H.264 recovery shim;
- Door or Gate behavior.

This release only exposes an explicit experimental Entrance target in the
Mini App WebCodecs tab.

## Safety

Development and release preparation performed no live Comelit media invocation.

The feature retains:

```text
automatic_retry=false
DOOR_ACTIONS=0
GATE_ACTIONS=0
```

A valid Mini App session is required before WebSocket upgrade, and a valid
start command is required before any Entrance manager acquire.

Invalid start commands therefore cannot open Comelit media.

## Offline validation

Feature PR #269 passed the repository Mini App, offline-safety, HACS and review
gates before merge.

New/updated tests cover:

- exact Entrance target admission while gate/other intercom targets remain
  rejected;
- invalid start command causes zero manager acquires;
- one Entrance start uses exactly one manager acquire;
- local SDP source is used rather than `camera.stream_source()`;
- PyAV SDP input is restricted to the local `file,udp,rtp` protocol set;
- source kind / media-start flags are emitted;
- source closes and manager lease is released;
- client WebSocket close releases the Entrance manager lease without waiting
  for the long session timeout;
- busy manager state fails closed before a second acquire;
- browser mock selects Entrance and renders a protocol-v2 H.264 frame;
- ordinary-camera WebCodecs behavior remains covered.

## Next live acceptance

After installing 1.7.26 and restarting Home Assistant, perform exactly one
explicit 60-second canary:

```text
entity=camera.comelit_entrance
duration=60s
automatic_retry=false
door_actions=0
gate_actions=0
```

The live run should establish:

1. actual Comelit bootstrap duration;
2. time from Comelit-media-ready to local SDP source open;
3. time to first H.264 AU;
4. WSS/CloudPub transport drift;
5. browser decode/render contribution;
6. clean media teardown and listener restoration after Stop.

No production architecture switch is made by this release.
