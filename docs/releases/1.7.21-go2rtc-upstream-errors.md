# Comelit 1.7.21 — expose go2rtc upstream MSE errors

## Purpose

1.7.21 is diagnostic-only. It does not change Mini App playback behavior.

## Why

The 1.7.20 live capture established that after MSE negotiation is forwarded:

```text
stream_state_250ms  producers=[{},{}] consumers=null
stream_state_4000ms producers=[{},{}] consumers=null
```

This means no producer connection had been established and no consumer had yet
been attached at those sample points.

Reviewing upstream go2rtc revealed an additional diagnostic blind spot. Its
WebSocket API reports handler failures as:

```json
{"type":"error","value":"mse: <error>"}
```

Comelit previously parsed and forwarded only valid `type=mse` MIME responses.
Other upstream text frames, including `type=error`, were silently ignored.

## New diagnostics

### Upstream WebSocket text

Every upstream text frame is now logged through:

```text
COMELIT_MINIAPP_DIAG_GO2RTC_WS
```

The log preserves:

- upstream frame type;
- useful error/detail text;
- elapsed time from MSE request start.

URL/IP/credential-style material is redacted before logging.

Valid `type=mse` MIME responses are still the only upstream text frames that
are forwarded to the Mini App. Diagnostic logging does not expand the browser
protocol surface.

### 7-second stream-state snapshot

In addition to the existing approximately 250 ms and 4 s snapshots, 1.7.21 adds:

```text
stream_state_7000ms
```

This samples the same read-only HA-managed go2rtc stream state shortly before
the unchanged 8 s MSE negotiation deadline.

## Interpretation

A live run can now distinguish:

1. go2rtc returns `type=error`:
   the sanitized error text should identify codec matching, ffmpeg/source,
   producer, or other AddConsumer failure directly;

2. no upstream text arrives and the 7 s snapshot still has
   `producers:[{},{}], consumers:null`:
   the evidence points to producer startup/Dial still being unresolved before
   the timeout;

3. producer/consumer state appears between 4 s and 7 s:
   startup timing, rather than immediate negotiation failure, becomes the next
   target.

## Unchanged behavior

1.7.21 does not change:

- camera source preparation;
- Generic Camera producer setup;
- MSE codec list;
- MSE timeout budgets;
- WebRTC fallback;
- HLS fallback;
- Comelit entrance-camera lifecycle;
- Door/Gate paths.

`camera.parking_6048` once while capturing:


The key new evidence is either an upstream `type=error` line or the
`stream_state_7000ms` snapshot.

No Door or Gate action is required.
