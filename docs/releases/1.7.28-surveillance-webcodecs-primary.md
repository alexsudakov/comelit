# Comelit 1.7.28 — surveillance WebCodecs primary viewer

## Purpose

Release 1.7.28 promotes the already live-validated ordinary-camera
WebCodecs/WSS transport to the normal Telegram Mini App
«Видеонаблюдение» viewer.

The production path for ordinary allowlisted H.264 cameras is now:

```text
explicit Surveillance tab / camera selection
  -> embedded WebCodecs viewer
  -> /api/comelit/miniapp/camera/{entity_id}/webcodecs
  -> camera.stream_source()
  -> PyAV H.264 demux/repackaging only
  -> bounded Annex-B WSS protocol v2
  -> Telegram Android WebView VideoDecoder
  -> canvas
```

No new camera transport, second media owner, transcoder, or permanent camera
preload is introduced.

## Primary transport and fallback

For ordinary surveillance cameras:

```text
PRIMARY = WebCodecs/WSS
FALLBACK = existing MSE -> WebRTC -> HLS viewer
```

The legacy viewer is not removed. It remains the automatic fallback when the
primary path cannot be used or ends terminally.

Covered fallback conditions include:

- WebCodecs / VideoDecoder unavailable;
- decoder or codec setup failure;
- WSS/source startup failure;
- source EOF or other terminal source errors;
- bounded backlog/runtime failure;
- ordinary WebCodecs session duration limit;
- a camera that is already unavailable when the viewer is opened.

For an initially unavailable camera, the legacy Home Assistant picture viewer
is mounted directly so later Home Assistant state recovery can still be
reflected without requiring a manual camera switch.

## Viewer lifecycle

Ordinary camera playback remains explicit and non-persistent.

Entering «Видеонаблюдение» or explicitly selecting a camera may start one new
WebCodecs session. Merely listing cameras does not preload them.

A healthy connected WebCodecs viewer is preserved across semantically unchanged
card renders and routine Home Assistant state refreshes.

Selecting another camera or leaving «Видеонаблюдение»:

```text
old embedded viewer disconnect
  -> WebSocket close
  -> PyAV/source cleanup
  -> no hidden ordinary stream kept alive
```

Generation guards ensure that late/stale callbacks from a disconnected viewer
cannot switch the new/current camera into legacy fallback.

## Session limits

The ordinary server-side WebCodecs session ceiling is now 600 seconds.

The diagnostic WebCodecs canary remains client-bounded to 60 seconds.

For embedded ordinary surveillance, a server `duration_limit` is terminal for
that primary session and automatically switches to the existing legacy
MSE -> WebRTC -> HLS viewer.

This does not change the Entrance media-manager contract.

## Entrance boundary

The Entrance camera remains a separate lifecycle domain.

Its normal viewer continues to use:

```text
Entrance
  -> manager-owned WebCodecs
  -> existing HLS fallback
```

The existing 600-second `ComelitMediaSessionManager` ceiling remains
authoritative for Entrance and does not become an automatic HLS restart.

No second Comelit P2P/CTPP session, media owner, or automatic native-media retry
is introduced by this release.

## Debug WebCodecs tab

The diagnostic WebCodecs tab remains available only when explicitly enabled:

```text
webcodecs_debug=1
```

The normal production Mini App surface remains:

```text
[ Домофон ] [ Видеонаблюдение ]
```

Ordinary production WebCodecs primary playback is enabled independently through
the Mini App card configuration with `webcodecs.surveillance_primary=true`.

Default Lovelace use outside the Mini App is not opted into this transport by
the release.

## Security and media boundary

Existing security boundaries are preserved:

- Mini App authentication/session validation is unchanged;
- ordinary cameras remain restricted to the configured surveillance allowlist;
- camera source URLs and credentials remain server-side;
- PyAV demuxes/repackages compressed H.264 only;
- no server-side video decode, encode, re-encode, scale, filter, or transcode is added;
- WSS framing remains closed and bounded;
- legacy go2rtc/HLS capabilities remain behind the existing same-origin Mini App endpoints.

## Door and Gate

Door and Gate behavior is unchanged.

```text
DOOR_ACTIONS_FROM_MEDIA_START=0
GATE_ACTIONS_FROM_MEDIA_START=0
automatic_retry=false
```

No camera-view operation in this release creates a Door or Gate action.

- Validate HACS;
- CodeRabbit review.

CodeRabbit identified one real edge case before merge: an ordinary camera that
was already unavailable could otherwise leave the new primary path on a static
notice and miss later state recovery. The fix restores the legacy viewer for
that case and includes a browser regression.

## Deployment boundary

Publishing the release does not itself restart Home Assistant and does not run
a live camera session.

The release is intended to be installed through HACS. After installation,
Home Assistant must load the updated integration/frontend runtime before
production acceptance.

Any explicit Home Assistant restart remains a separate user-authorized action.
No Door/Gate operation or live Comelit canary is required by release
preparation itself.
