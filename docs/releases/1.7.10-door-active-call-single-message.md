# 1.7.10 - Door active-call single message

Status: **release-ready / physical Ring acceptance required**

## Defect

Version 1.7.9 added native observability but left the Entrance Door action on
the wrong protocol profile during an already active physical Ring call. The
observed native markers showed the Door request still following the standalone
Door profile instead of the attached call transaction.

Observed defect markers:

- `V4_DOOR_EXISTING_CTPP_REUSED=true`
- `V4_DOOR_OPERATION_WRITES_SENT=5`
- `V4_DOOR_DOOR_SPECIFIC_ACK_PROVEN=false`
- `V4_DOOR_PHYSICAL_EFFECT_ASSERTED=false`

## Root Cause

The attached-media listener lineage was correct, but the Door command profile
was not. During active Ring media, the listener owns the live call transaction;
using the standalone five-write Door profile was the wrong profile for that
state.

## Fix

R66 adds a bounded Entrance-only call-time Door path. When the existing listener
is in an active attached call, the Door command is serialized as a single
call-time frame on the existing call transaction.

A pre-release review found and corrected an ordering defect in the first R66
candidate: the call-time predicate was evaluated once while the Door state was
IDLE, then evaluated again after the normal transition to SENDING. Because the
predicate required IDLE, that second evaluation would have fallen back to the
legacy five-write profile. The final R66 implementation now records the selected
profile before the transition and uses a separate fail-closed queue-time
predicate that expects SENDING. The emitted `V4_DOOR_PATH=CALL_TIME_SINGLE`
marker is produced only after the call-time frame is actually queued.

Expected R66 markers:

- `V4_DOOR_PATH=CALL_TIME_SINGLE`
- `V4_CALL_TIME_DOOR_COMMAND_ACCEPTED=true`
- `V4_CALL_TIME_DOOR_QUEUED=true`
- `V4_CALL_TIME_DOOR_SENT=true`
- `V4_CALL_TIME_DOOR_WRITE_COUNT=1`
- `CALL_SEQUENCE_BEFORE=<0..255>`
- `CALL_SEQUENCE_AFTER=<0..255>`
- `CALL_TIME_DOOR_ACK_OBSERVED=<true|false>`
- `CALL_TIME_DOOR_SEQUENCE_COMMITTED=<true|false>`
- `CALL_TIME_DOOR_STALE_GENERATION=true` only if the live call generation
  changes before pending TX completion.

## Safety Invariants

- no second CTPP/P2P session is opened;
- no automatic retry is added;
- ACK observation is not physical-effect proof;
- Gate behavior is outside the change;
- standalone Door bytes remain byte-identical;
- the media lifecycle remains owned by the attached listener path;
- a pending call-time Door TX never overwrites the sequence of a newer call
  generation: sequence commit requires the saved generation, call readiness,
  and saved prior sequence to still match.

The Home Assistant-side `door_one_shot_sequence_sent()` classifier still
requires `write_count == 5`. That owner decision is intentionally not changed
in this PR; R66 is classified by `V4_DOOR_PATH=CALL_TIME_SINGLE`, not by the
standalone write-count heuristic.

## Physical Acceptance

After installing 1.7.10 and restarting Home Assistant:

1. trigger one real entrance-panel Ring;
2. wait for attached media to become active;
3. press Entrance Door exactly once while the call media is still active;
4. expect `V4_DOOR_PATH=CALL_TIME_SINGLE`;
5. expect `V4_CALL_TIME_DOOR_WRITE_COUNT=1`;
6. verify `CALL_SEQUENCE_AFTER == (CALL_SEQUENCE_BEFORE + 1) mod 256`;
7. record `CALL_TIME_DOOR_ACK_OBSERVED=<true|false>`;
8. record physical Door observation separately from software ACK markers;
9. confirm attached media remains healthy and terminates only according to the
   normal call/media lifecycle.

Do not treat this release as evidence for Door during separately bootstrapped
manual/on-demand media. This release covers the active physical Ring call path
on the existing listener-owned call transaction.
