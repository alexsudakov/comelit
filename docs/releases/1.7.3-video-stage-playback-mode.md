# 1.7.3 — Mini App video viewport and transport-label fix

Status: **release-ready / production canary required**

## Observed on 1.7.2

A parking-camera HLS fallback produced working video, but two UI defects remained:

1. the surveillance video escaped the intended compact viewport and consumed most of the Mini App screen;
2. after HLS fallback, the final label could incorrectly read `WebRTC · первый кадр 0.0 с`.

## Root cause

The viewer constrained the `<video>` element directly. Telegram WebView still allowed intrinsic media sizing to dominate the layout.

The transport-label error came from a pending WebRTC `requestVideoFrameCallback`. After the same `<video>` element was switched to HLS, the first HLS frame fired that stale callback and was misreported as a WebRTC frame.

## Fix

- add an explicit `.miniapp-video-stage` wrapper with a bounded height;
- absolutely fit the media element inside that stage with `width/height: 100%` and `object-fit: contain`;
- keep separate surveillance and intercom stage sizes;
- track the active playback mode;
- ignore stale WebRTC first-frame callbacks after switching to HLS.

## Unchanged

- no camera preload;
- no Frigate dependency;
- WebRTC/HLS selection logic from 1.7.2 is unchanged;
- Comelit entrance-camera transport is unchanged;
- Door/Gate behavior is unchanged.
