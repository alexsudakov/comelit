# 1.7.9 — bounded Door native observability

Status: **diagnostics release / one physical attached-Ring acceptance required**

## Why

The 1.7.8 physical test proved that attached inbound media can become active
and the Home Assistant Door service is no longer rejected solely because
`attached_media_busy=true`, but the physical entrance Door did not open.

Historical read-only forensics could recover only the conservative ledger
state `UNKNOWN_OUTCOME`. The decisive native markers were consumed internally
by `runtime.py` and were not emitted to Home Assistant logs, so that result
could not distinguish:

- native Door command not accepted;
- command accepted but fewer than five writes completed;
- all five writes completed but no physical effect / Door-specific ACK;
- Home Assistant's 10-second wait expiring without a native result.

## Change

This release adds a dedicated bounded Door evidence log surface.

For each one-shot Door attempt Home Assistant now logs:

- operation id and requested bounded Door target;
- whether attached media is open/busy and listener readiness at start;
- a native-result timeout marker if the 10-second wait expires;
- the final conservative runtime result.

Only allowlisted native Door facts are emitted:

- target-valid and command-accepted booleans;
- target `entrance` or `gate`;
- existing-CTPP reuse;
- individual write 1..5 completion markers;
- bounded write count 0..5;
- Door-specific ACK proof;
- bounded reject stage / reject response word;
- final Door result.

The log surface intentionally excludes CTPP/request/response channel IDs,
raw native lines, Door payload bytes, network addresses, SDP, media data,
tokens and credentials.

## Behavior unchanged

This release does not change:

- the SIGUSR1 one-shot boundary;
- the five Door write bodies;
- target selection;
- existing CTPP reuse;
- Door retry policy (still no automatic retry);
- attached-media lifecycle;
- 1.7.8 routing semantics.

A separate static audit also confirms attached media does not move the main P12
state away from `V4_LISTEN_RING`; the listener Door signal handler and Door
tick remain present in the R42 lineage.

## Next physical acceptance

After installing 1.7.9 and restarting Home Assistant, perform exactly one
physical entrance Ring test:

1. wait until attached camera media is active;
2. press Entrance Door once;
3. do not retry;
4. collect the bounded Door evidence and attached-media timeline.

Classification becomes deterministic:

- no `V4_DOOR_COMMAND_ACCEPTED=true` -> investigate signal/tick/native
  readiness;
- accepted but fewer than five write completions -> investigate Door TX path;
- five writes completed -> investigate call-time Door protocol/target/ACK
  semantics rather than Home Assistant routing.
