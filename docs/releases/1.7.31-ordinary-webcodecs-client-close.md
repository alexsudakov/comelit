# Comelit 1.7.31 — prompt ordinary WebCodecs client-close teardown

Release 1.7.31 includes the Mini App ordinary-camera lifecycle correction from
[PR #279](https://github.com/alexsudakov/comelit/pull/279).

Production acceptance of release 1.7.30 exposed that an ordinary surveillance
WebCodecs session could remain alive after the embedded viewer left
«Видеонаблюдение». The browser already removed the viewer from the DOM and
closed its WebSocket, but the backend had a receive-side close watcher only for
the Entrance branch. An ordinary RTSP session could therefore remain blocked on
its source queue until a later send observed the disconnected client.

Entrance and ordinary WebCodecs sessions now use one shared receive-side
WebSocket close watcher after the initial WebCodecs command. A client close
wakes the existing session queue promptly, so normal cleanup cancels the source
task, closes the H.264/PyAV source through the serialized owner-thread contract,
releases the WebCodecs session lease, and emits the final session summary.

A bounded `client_close` lifecycle event is also logged so production
acceptance can distinguish client-close detection from the later
`session_close` summary.

The correction does not change the WebCodecs protocol or frame format, the
ordinary camera source configuration, fallback policy, Entrance warm-park
ownership, the 600-second media ceilings, Door/Gate behavior, or the native
Comelit helper/protocol.

## Evidence and validation

The production observation that motivated this correction was made on 1.7.30:
an ordinary `camera.dvor_1` WebCodecs session remained open for about 45
seconds even though the user viewed it for about five seconds and then left the
Surveillance tab. Existing 1.7.30 logs did not expose the exact client-close
timestamp, but static inspection confirmed the Entrance-only receive watcher.

Feature merge: `bb92cda70bb80dda5437e6bb8cf678ddc4d8fde3`.

Validation on PR #279:

- Mini App pytest suite passed after updating the WebSocket test harness to
  model persistent client connections explicitly;
- browser WebCodecs and viewer regressions passed, including the existing
  assertion that leaving Surveillance closes the client WebSocket;
- `offline-safety` passed;
- Validate HACS passed;
- no live camera run, HA deployment, HA restart, Door action, or Gate action was
  performed for the code change.

## Installation

Update to 1.7.31 through HACS and restart Home Assistant to load the corrected
Python runtime. Publishing this release does not install it or restart HA.

After updating, production acceptance should verify that an ordinary camera
session emits `client_close` promptly after leaving «Видеонаблюдение», followed
by `session_close`, and that the Entrance → Surveillance → Entrance warm-return
flow remains intact.
