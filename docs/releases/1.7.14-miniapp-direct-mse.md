# Comelit 1.7.14 — direct MSE live view for Telegram Mini App surveillance cameras

## Summary

1.7.14 changes the primary Telegram Mini App playback path for ordinary Home
Assistant surveillance cameras from WebRTC-first to MSE/fMP4 over a restricted
same-origin WebSocket.

The new path is:

```text
Home Assistant camera entity
  -> Camera.stream_source()
  -> HA-managed go2rtc
  -> Comelit restricted MSE/WSS proxy
  -> Telegram Mini App
```

Playback priority for ordinary surveillance cameras is:

```text
MSE -> WebRTC -> HLS
```

No standalone go2rtc process, add-on, VM, container or application server is
introduced.

The Comelit entrance camera is intentionally excluded from this path and keeps
its separately validated Comelit media-manager -> Home Assistant HLS lifecycle.

## Camera configuration and credentials

The existing Home Assistant camera entity remains the source of truth.

For an ordinary surveillance camera, Comelit resolves the live Camera object and
uses:

```python
await camera.stream_source()
```

The integration does not read integration-private username/password fields and
does not add duplicate camera URL/login/password settings to the Comelit
Options Flow.

The resolved source may contain credentials, but it remains server-side.

It is not serialized into:

- Mini App HTTP responses;
- Mini App WebSocket control messages;
- diagnostics payloads;
- formatted diagnostics logs;
- Mini App bootstrap/state data.

The browser receives only the authenticated Comelit Mini App media channel.

## HA-managed go2rtc integration

The Mini App reuses the go2rtc instance already managed by Home Assistant.

For each ordinary camera viewer, Comelit uses an opaque internal stream name and
a bounded in-process lease/refcount lifecycle.

The first viewer registers the source for Mini App use. Additional viewers can
share that producer. Disconnect, session expiry, upstream failure and navigation
all release the viewer lease; the last release removes the Mini App-owned
registration.

The implementation is isolated behind a small compatibility adapter. If the
expected HA-managed go2rtc runtime surface is unavailable or incompatible, the
Mini App fails over instead of preventing the integration from loading.

## Restricted MSE proxy

The browser connects only to the Comelit same-origin endpoint for the selected
allowed surveillance camera.

The endpoint:

- enforces the existing Mini App session;
- rechecks the camera against the configured surveillance allowlist;
- rejects the Comelit entrance camera;
- accepts only the bounded MSE codec-negotiation command;
- rejects arbitrary go2rtc control commands;
- relays only the bounded MSE response/error plus binary fMP4 chunks;
- closes and cleans up the upstream go2rtc WebSocket in all terminal paths.

The internal source name, go2rtc management URL and resolved camera source are
not exposed to the browser.

## Player lifecycle

On clients with MediaSource or ManagedMediaSource, MSE starts immediately.

Current bounded startup deadlines are:

- MSE negotiation: 3 seconds;
- first media chunk: 6 seconds;
- first decoded/rendered frame: 12 seconds.

A successful WebSocket connection or MSE MIME negotiation alone is not treated
as successful playback. The first decoded/rendered frame remains the success
milestone.

If MSE is unavailable or fails its bounded startup, the existing WebRTC path is
used. If WebRTC fails, the existing session-bound HLS proxy remains the final
fallback.

The existing WebRTC session/candidate ordering, explicit close behavior and
zero-RTP fallback policy remain available as fallback behavior.

## Diagnostics

The closed Mini App diagnostics schema now includes bounded MSE milestones and
failure reasons, including connection, negotiation readiness, first chunk, first
frame, error and fallback evidence.

Diagnostics remain enums/integers/bounded counters only.

They do not include camera URLs, credentials, IP addresses, go2rtc management
credentials, Telegram initData, cookies, SDP/candidate strings or media payload.

## Security regression proof

The Mini App regression suite includes a credential-bearing camera source
fixture:

```text
rtsp://test-user:test-password@192.0.2.10/example
```

The fixture is proven to reach the go2rtc adapter while tests assert that the
full source, username and password do not appear in HTTP responses, WebSocket
control messages, diagnostics payloads or formatted logs.

The leak check is non-vacuous: deliberately introducing the test secret makes
the assertion fail.

## Live evidence boundary

The new MSE path is production-ready by repository tests and CI, but its startup
latency on the installation remains **NOT_PROVEN** until post-update live
acceptance.

Recommended acceptance after updating to 1.7.14:

1. update the Comelit integration to 1.7.14;
2. restart Home Assistant as required for the custom integration update;
3. open the Telegram Mini App surveillance camera `Паркинг 6048`;
4. verify that the selected transport is MSE rather than WebRTC/HLS;
5. capture bounded diagnostics for MSE connect, first chunk and first frame;
6. compare first-frame latency with the previous WebRTC/HLS baseline;
7. navigate away and confirm the viewer/producer is released.

The entrance-camera Comelit media lifecycle and Door/Gate safety boundaries are
not part of this acceptance.
