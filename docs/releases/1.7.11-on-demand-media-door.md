# Comelit 1.7.11 — Entrance Door during on-demand camera media

## Summary

1.7.11 extends the active-video Entrance Door profile to the separately
bootstrapped on-demand entrance-camera session.

When there is no physical Ring and the user explicitly opens
`camera.comelit_entrance`, the persistent listener is intentionally paused and
`comelit-media` owns the exclusive Comelit connection. Entrance Door is now
routed to that active media owner instead of failing closed.

## Protocol profile

The media helper sends exactly one 48-byte active-video Door message on the
existing media CTPP:

- CTP prefix: `0x1840`
- action: `0x000D`
- relay index: `1`
- target: Entrance only
- existing CTPP reused
- no second P2P session
- no second CTPP open
- no automatic retry

This is the same PCAP-derived Android active-video Door profile used by the
1.7.10 attached physical-call fix, but it is executed by a different connection
owner: `comelit-media` instead of the persistent listener.

## Home Assistant routing

While the persistent listener owns the connection, Door routing is unchanged.

While a separately bootstrapped on-demand media session owns the connection:

- Entrance Door is available only when that media transport is actually active;
- the button and `comelit.open_door` service dispatch to the active media
  transport;
- Gate remains fail-closed;
- the same safe `comelit_door_operation` event is emitted;
- physical effect is never inferred from local transmission or protocol ACK.

## Safety

- Entrance only in the on-demand media profile.
- Gate is not promoted to this profile.
- No automatic retry.
- No second cloud/P2P bootstrap.
- No second CTPP open.
- Door action is rejected unless on-demand media is fully active.
- Physical opening remains an owner-observed acceptance result.

## Acceptance still required

Two physical scenarios should be validated after upgrading to 1.7.11:

1. physical Ring → attached video → one Entrance Door press;
2. no Ring → explicitly open entrance camera → one Entrance Door press.

The first validates the 1.7.10 listener-owned call-time path; the second
validates the new P122 media-owned path.
