# Comelit 1.7.15 — fix Mini App MSE binding to HA-managed go2rtc

## Summary

1.7.15 fixes two production defects found after live use of 1.7.14.

The intended ordinary-camera transport remains:

```text
Camera.stream_source()
  -> HA-managed go2rtc
  -> restricted Comelit MSE/WSS proxy
  -> Telegram Mini App
```

with fallback:

```text
MSE -> WebRTC -> HLS
```

In 1.7.14, the MSE path could fail before media startup and fall through to the
older WebRTC/HLS path.

## Defect 1 — Home Assistant go2rtc runtime shape

Current Home Assistant stores go2rtc runtime state in `hass.data["go2rtc"]` as
a `Go2RtcConfig(url, session)` object.

1.7.14 incorrectly expected a plain URL string.

For HA-managed go2rtc this is especially important because Home Assistant
normally disables the TCP HTTP listener and communicates with go2rtc through
the runtime ClientSession, which carries the UnixConnector and generated
authentication.

1.7.15 now feature-detects the runtime object and reuses its authoritative
`url` and `session`.

A bounded compatibility path remains for older/string-only runtimes.

## Defect 2 — MSE codec negotiation

The go2rtc MSE protocol expects concrete MP4 codec identifiers.

1.7.14 incorrectly sent generic tokens such as:

```text
h264
h265
```

1.7.15 aligns the Mini App negotiation with upstream go2rtc VideoRTC and sends
browser-supported identifiers such as:

```text
avc1.640029
avc1.64002A
avc1.640033
hvc1.1.6.L153.B0
mp4a.40.2
mp4a.40.5
flac
opus
```

The server-side closed allowlist was updated to accept only these bounded codec
identifiers.

## Regression coverage

The new test suite explicitly verifies the real Home Assistant runtime shape.

The adapter test fails if the implementation tries to replace the runtime
go2rtc ClientSession with a normal Home Assistant aiohttp session.

All valid MSE protocol tests now use concrete go2rtc codec identifiers, and the
browser regression verifies that the Mini App sends the same identifiers that
upstream go2rtc expects.

## Live evidence boundary

The production symptom on 1.7.14 was an ordinary surveillance camera falling
through to HLS and taking more than 20 seconds for the first frame.

The two code defects that explain that fallback are fixed in 1.7.15.

Actual MSE first-frame latency on the installation remains to be measured after
updating to 1.7.15.
