# Comelit 1.7.23 — disable go2rtc ONVIF backchannel probe for Generic RTSP MSE

## Production evidence

The 1.7.22 live capture confirmed that removing the Generic Camera `ffmpeg:`
wrapper was not sufficient. The Mini App registered exactly one direct RTSP
producer, but that producer was still unresolved through the full MSE window:

```text
mse_negotiation_forwarded   ~54 ms
stream_state_250ms          producer_count=1, active=0, consumer_count=0
stream_state_4000ms         producer_count=1, active=0, consumer_count=0
stream_state_7000ms         producer_count=1, active=0, consumer_count=0
mse_fallback                8001 ms
```

No upstream go2rtc `type=error` message was emitted.

## Upstream go2rtc behavior

go2rtc's RTSP handler creates new RTSP clients with:

```text
Backchannel=true
```

by default.

Its first DESCRIBE therefore includes the ONVIF backchannel requirement:

```text
Require: www.onvif.org/ver20/backchannel
```

If that DESCRIBE fails, go2rtc reconnects and retries DESCRIBE with backchannel
disabled.

The same RTSP client uses a 5 second response read deadline. A camera that does
not support, ignores, or slowly rejects the ONVIF backchannel DESCRIBE can
therefore consume most of the Mini App's 8 second MSE negotiation budget before
the ordinary receive-only retry begins.

## Change

For Mini App MSE only, Home Assistant Generic Camera RTSP sources now add:

```text
#backchannel=0
```

before registration in HA-managed go2rtc.

If the resolved source already contains a go2rtc fragment, the integration
appends:

```text
&backchannel=0
```

instead.

This tells go2rtc to skip the initial ONVIF-backchannel DESCRIBE and negotiate
the ordinary receive-only RTSP stream immediately.

## Scope

The change is intentionally narrow:

- applies only to Generic Camera RTSP/rtsps sources;
- applies only to Mini App MSE registration;
- other camera platforms keep the exact resolved source;
- Home Assistant's own WebRTC provider is unchanged;
- WebRTC fallback remains unchanged;
- HLS fallback remains unchanged.

The RTSP source and credentials stay inside Home Assistant/go2rtc and are never
serialized to the browser.

## Live acceptance

After installing 1.7.23 and restarting Home Assistant, open
`camera.parking_6048` once with the existing diagnostics capture.

A successful hypothesis should change the earliest go2rtc state from an empty
producer to an active RTSP producer and then produce the normal MSE sequence:

```text
mse_negotiation_forwarded
-> producer active / medias discovered
-> mse_upstream_reply
-> mse_upstream_chunk
-> mse_ready
-> mse_first_chunk
-> mse_first_frame
```

If the producer is still unresolved at 4–7 seconds, the ONVIF-backchannel
hypothesis is closed and the next investigation should focus on the camera's
plain RTSP DESCRIBE/startup behavior itself.

No Door or Gate action is required.
