# Comelit 1.7.13 — repeated manual Entrance Door presses during on-demand media

## Summary

1.7.13 removes the session-wide P122 `DOOR_ALREADY_SENT` lockout that was
observed after the first successful Entrance Door command during an active
on-demand camera session.

The first explicit manual Door operation remains one operation -> one native
Door write. A later explicit manual press may now be accepted in the same
active on-demand media session after the previous operation has completed its
bounded 1000 ms inflight/settle window.

Automatic retry remains forbidden.

## Runtime behavior

The P122 native helper now keeps two separate concepts:

- `p122_door_inflight`: the current operation is still inside its bounded
  1000 ms settle window; another press remains fail-closed as
  `DOOR_INFLIGHT`.
- completed Door TX provenance: after native TX completion, the last Door
  sequence is committed and becomes the sequence source for a later distinct
  manual operation.

The permanent session-wide `DOOR_ALREADY_SENT` eligibility gate is removed.

For each later explicit press:

1. all normal P122 active-media eligibility gates must still pass;
2. no Door operation may be inflight;
3. the existing active media CTPP is reused;
4. the new Door packet advances the last completed Door TX sequence by the
   existing `0x00010000` sequence step;
5. exactly one native Door write is permitted for that operation;
6. no automatic retry is performed.

## Safety boundaries

Unchanged:

- Entrance only for the P122 on-demand media Door profile.
- Gate remains fail-closed while separately bootstrapped on-demand media owns
  the Comelit connection.
- No second P2P or CTPP bootstrap.
- No overlapping Door TX.
- One native write maximum per explicit operation.
- Automatic retry is false.
- Post-send ambiguity remains terminal `UNKNOWN_OUTCOME`.
- Generic protocol ACK is not proof that the physical entrance opened.
- `physical_effect_asserted=false` remains authoritative without independent
  physical feedback.
- The listener-owned R66 / `CALL_TIME_SINGLE` path is not changed.

## Live evidence boundary

Release 1.7.12 already established that the first accepted P122 Door operation
can physically open the entrance door.

A **second transmitted manual Door operation in the same active on-demand media
session** has not yet been physically validated. That behavior remains
`NOT_PROVEN` until a user-driven post-update acceptance test is performed.

Recommended acceptance after updating to 1.7.13:

1. start one on-demand entrance camera session with no physical Ring;
2. press Entrance Door once and observe the physical result;
3. wait more than one second;
4. while the same media session remains active, press Entrance Door a second
   time;
5. capture logs and independently report the physical result of each press.

Expected transport-side evidence is two distinct operation IDs, one native write
for each accepted press, no `DOOR_ALREADY_SENT`, no automatic retry, and the
second sequence advancing the first completed Door TX sequence.
