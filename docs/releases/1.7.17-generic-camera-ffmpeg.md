# Comelit 1.7.17 — align Generic Camera MSE source preparation with Home Assistant

## Production evidence

After installing 1.7.16, a bounded live capture of `camera.parking_6048`
still showed:

```text
mse_connect   = 0 ms
mse_ready     = not observed
mse_first_chunk = not observed
mse_first_frame = not observed
mse_fallback  = 8001 ms
reason        = mse_negotiation_failed
```

The same entity was then verified in Home Assistant as:

```text
domain=generic
is_generic=True
```

That closed the remaining platform uncertainty for this camera.

## Root cause

Home Assistant core contains a specific go2rtc compatibility workaround for
Generic Camera entities:

```python
if camera.platform.platform_name == "generic":
    stream_source = "ffmpeg:" + stream_source
```

The Comelit Mini App MSE path correctly used the public
`await camera.stream_source()` contract, but then registered that raw
RTSP/HTTP source directly in HA-managed go2rtc.

That bypassed the same Generic Camera preparation used by Home Assistant's own
go2rtc provider.

## Fix

1.7.17 now applies the same compatibility rule for entity-registry platform
`generic`:

```text
camera.stream_source()
-> validate direct rtsp/rtsps/http/https source
-> ffmpeg:<stream_source>
-> HA-managed go2rtc
-> restricted Comelit MSE/WSS proxy
-> Mini App
```

For other ordinary camera integrations, the resolved source remains unchanged.

The source URL and any credentials remain server-side. The browser still sees
only the authenticated same-origin Comelit media endpoint.

## Safety and scope

The change does not:

- expose camera URLs or credentials;
- change Mini App authorization;
- alter Door or Gate paths;
- alter the Comelit entrance-camera media lifecycle;
- add a second go2rtc instance;
- change the MSE/WebRTC/HLS fallback order.

The raw source is validated before the internal `ffmpeg:` wrapper is applied.

## Regression coverage

PR #251 adds explicit tests that:

- Generic Camera is registered as `ffmpeg:<source>`;
- a non-generic ordinary camera keeps its original direct source;
- existing refcount and unregister behavior is unchanged;
- credential-bearing camera fixtures remain internal and do not leak to HTTP,
  WebSocket, diagnostics, or formatted logs.

During PR validation, two pre-existing Playwright fake-clock diagnostics races
were exposed in unrelated browser scenarios. Those tests were hardened to wait
for the throttled diagnostic event they assert instead of assuming delivery on
the same scheduler tick. No production behavior was changed for that test fix.

Required CI completed successfully:

- `miniapp`: PASS;
- `offline-safety`: PASS;
- `Validate HACS`: PASS.
