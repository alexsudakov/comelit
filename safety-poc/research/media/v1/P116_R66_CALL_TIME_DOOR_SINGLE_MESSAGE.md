# P116/R66 Call-Time Door Single Message

R66 addresses the 1.7.9 Door defect at the root stage `CALL_TIME_DOOR_PROTOCOL`: while an R35/R42 call is already active, the old Door path still used the standalone five-write profile instead of the active call transaction. The observed bounded markers for the new path are `V4_DOOR_PATH=CALL_TIME_SINGLE`, `V4_CALL_TIME_DOOR_COMMAND_ACCEPTED=true`, `V4_CALL_TIME_DOOR_QUEUED=true`, `V4_CALL_TIME_DOOR_SENT=true`, `V4_CALL_TIME_DOOR_WRITE_COUNT=1`, `CALL_SEQUENCE_BEFORE=<0..255>`, `CALL_SEQUENCE_AFTER=<0..255>`, and `CALL_TIME_DOOR_ACK_OBSERVED=<true|false>`.

The call-time wire contract is one 48-byte CTP packet. Bytes 0..1 are data/version (`0x40 0x18`), bytes 2..3 are the current R35 call CTP connection in big endian, byte 4 is the current call sequence, byte 5 is the current call ack, bytes 6..7 are inner length `13`, bytes 8..9 are opcode `0x002d`, bytes 10..19 are the destination logical address, bytes 20..23 are relay index 1 in little-endian form, bytes 24..27 are `ff ff ff ff`, bytes 28..37 are the source logical address, and bytes 38..47 are the apartment base from `V4_APT_ADDRESS`. The trailing 10 bytes intentionally use the apartment base (`00040117`) rather than the apartment+subaddress because the captured Door profile carries the base apartment identity in that slot.

Selection is fail-closed. The call-time path is chosen only for target `entrance`, listener ready, registered, `v4_ctpp_channel_id != 0`, `p12_stage == P12_STAGE_V4_LISTEN_RING`, Door idle, no pending P12 TX, `r35_call_ready(&g_r35_session)`, and R42 media stage `ACTIVE`. Any selector miss, including inactive media, stale call state, busy TX, missing registration, or target `gate`, falls through to the existing standalone path. The five standalone Entrance bodies remain byte-identical to R64, and Gate is not promoted to the call-time profile.

Sequence handling is bounded to TX completion. `CALL_SEQUENCE_BEFORE` is copied from `g_r35_session.call_sequence` before queueing; the wire byte equals that value; `CALL_SEQUENCE_AFTER=(before+1)&0xff` is committed only when `P12_TX_CALL_TIME_DOOR` completes. If queueing fails or the TX never completes, `g_r35_session.call_sequence` is not advanced.

ACK observation is derived but conservative. A bare CTPP response with prefix `0x1800` and action `0x0000`, on the existing CTPP channel while the R66 operation is in `V4_DOOR_WAIT_SETTLE`, sets `CALL_TIME_DOOR_ACK_OBSERVED=true`. Absence of that response leaves the marker false. This generic ACK is not promoted to Door-specific proof: `V4_DOOR_DOOR_SPECIFIC_ACK_PROVEN=false`, Home Assistant `protocol_acked=false`, and `physical_effect_asserted=false` remain the contract.

New markers and allowlist: `V4_DOOR_PATH` is allowlisted in `custom_components/comelit/runtime.py` via `_DOOR_LOG_PATHS`; `V4_CALL_TIME_DOOR_COMMAND_ACCEPTED`, `V4_CALL_TIME_DOOR_QUEUED`, `V4_CALL_TIME_DOOR_SENT`, and `CALL_TIME_DOOR_ACK_OBSERVED` are in `_DOOR_LOG_BOOLEAN_KEYS`; `V4_CALL_TIME_DOOR_WRITE_COUNT`, `CALL_GENERATION`, `CALL_SEQUENCE_BEFORE`, and `CALL_SEQUENCE_AFTER` are in `_DOOR_LOG_INTEGER_KEYS`.

Important classification note: when `V4_DOOR_PATH=CALL_TIME_SINGLE`, `V4_DOOR_WRITE_COUNT=1` / `V4_CALL_TIME_DOOR_WRITE_COUNT=1` means one call-time frame. It does not mean "1 of 5" standalone writes. The old heuristic `WRITE_COUNT < 5 => DOOR_TX_SEQUENCE` is not valid for this path; the classifier key is `V4_DOOR_PATH`.

The offline whole-TU stub-header changes are narrow compile-gate coverage fixes, not gate weakening. `glib/gstdio.h` now declares `g_unlink` because the generated shipped line calls it from `v4_door_read_target`; without that declaration the gate did not type-check the whole shipped line. `glib.h` uses real pointer-return signatures for `g_checksum_get_string` and `g_compute_checksum_for_data` to avoid spurious `-Wformat` diagnostics when the generated TU prints checksum strings. R57 still compiles under the same whole-TU gate.

Out of scope for R66: Gate semantics, standalone Door bodies, the attached-media helper, and the Home Assistant media lifecycle are unchanged. The result remains `UNKNOWN_OUTCOME`; R66 only adds a bounded active-call Door serializer and selector.

Evidence: `tests/native/p116_r66_call_time_door_host_harness.c` is compiled and executed by `tests.test_p116_r66_call_time_door`. It prepends the freshly generated R66 region, proves cases A-H at runtime, compares the generated C serializer against an independent 48-byte reference encoder with an inversion, verifies sequence advance/no-advance behavior, checks ACK marker true/false derivation, and asserts stdout does not expose raw addresses, connection id, channel id, or payload bytes. `tests.test_p116_r60_door_gate_contract` covers Home Assistant marker allowlisting and the conservative `protocol_acked=false` / `physical_effect_asserted=false` result. `tests.test_p116_r57_whole_tu_compile_gate` keeps the whole generated translation unit type-checked.
